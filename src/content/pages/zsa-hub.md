overview:
  title: "What are Zcash Shielded Assets?"
  paragraphs:
    - "OrchardZSA extends Zcash's Orchard shielded protocol so that any user-defined asset can be issued, transferred, and burned inside the same shielded pool as ZEC, with the same privacy guarantees. Where most chains expose the sender, receiver, amount, and asset type of every token transfer, a ZSA transfer reveals none of them."
    - "OrchardZSA is a full protocol, not a feature. It defines new issuance keys and asset identifiers, a note and commitment structure for custom assets, Action Groups and a new transaction format, consensus rules for supply tracking and finalization, and an updated fee model. It is specified across interdependent ZIPs, independently audited, and implemented across multiple repositories of the Zcash stack, from the halo2 proving system to the Zebra node."
    - "The implementation is complete and is kept up to date as the upstream code evolves. It is ready to be merged into the main Zcash repositories behind a feature flag. Whether ZSAs activate on Mainnet is now a decision for the Zcash community."

whyItMatters:
  title: "Shielded assets improve blockchain privacy"
  paragraphs:
    - "Zcash offers the strongest financial privacy in the world. Using zero-knowledge proofs, it cryptographically proves a transaction is valid without revealing the sender, receiver, or amount. Unlike other protocols, which rely on privacy add-ons or trusted third parties, Zcash was designed with a privacy-first mindset."
    - "Today, those privacy guarantees only apply to ZEC (Zcash's native token) - not the stablecoins, tokenized assets, or NFTs people actually want to move privately."
    - "ZSAs change that. They bring arbitrary assets into Zcash's shielded pool, giving stablecoins, tokens, and NFTs the same privacy as ZEC, and turning the world's most private network into a home for the entire asset economy."

faq:
  title: "FAQ"
  items:
    - question: "When will ZSAs ship?"
      answer: "The implementation is complete. What remains is maintenance: rebasing it onto upstream as the Zcash codebase moves, as was done for the NU6.3 (Ironwood) upgrade. OrchardZSA is specified, independently audited and implemented across the Zcash stack. It is ready to be merged into the main Zcash repositories behind a feature flag, so it can sit in the codebase without changing behaviour until it is switched on. Activating ZSAs on Mainnet requires a network upgrade, and which features a network upgrade includes is decided by the Zcash community. ZSAs are not part of NU7."
      linkLabel: "NU7 scope"
      linkHref: "https://forum.zcashcommunity.com/t/nu7-timeline/57655"
    - question: "Why has it taken several years?"
      answer: "ZSAs change how value is issued and moved, so they touch consensus-critical code in multiple repositories, from the halo2 proving system to the Zebra node. Each change has to pass upstream review by the teams that maintain those repositories. Over the same period the base protocol kept moving: the zcashd deprecation, NU6.1, the NU6.2 circuit fix, the NU6.3 Ironwood pool and two redesigns of the transaction format. Every one of these required updating and rebasing the ZSA implementation, then taking it back through review."
      linkLabel: "NU6.3 Ironwood"
      linkHref: "https://forum.zcashcommunity.com/t/ironwood-verifying-the-soundness-of-zcash-s-circulating-supply/56044/61"
    - question: "What applications will ZSAs enable?"
      answer: "ZSAs make Zcash a home for private versions of the assets people actually use. That includes stablecoins that move with full shielded privacy (and, via transaction controls, with compliance where it's required), private and atomic asset swaps directly on Zcash, tokenized real-world assets and NFTs that stay confidential, and wrapped or bridged assets brought over from other chains. In short, any asset that benefits from strong privacy becomes possible on the world's most private financial network."
    - question: "Is OrchardZSA audited?"
      answer: "Yes. Least Authority completed an independent security audit of the OrchardZSA protocol, with the final report completed in January 2025. The report is linked in the Security & Audits section above."
    - question: "How can I start building with ZSAs?"
      answer: "Start with the specifications (ZIPs 226, 227 and 228) and QEDIT's zcash_tx_tool for constructing and testing ZSA transactions on the feature testnet, all linked above. If you're planning an integration or have a specific use-case in mind, get in touch - we designed the protocol and are happy to help."
